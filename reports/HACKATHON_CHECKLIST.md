## Три исправленных несоответствия

### HR/администратор — исправлено

Миграция 003_hr_role.sql добавляет роль hr в существующую базу. Тестовый аккаунт hr@janamen.local получает отдельный кабинет: каталог с поиском и заявки своей компании со статусами, карточками и историей. HR не подаёт, не отзывает и не согласует отпуск вместо сотрудника или прямого руководителя. Официальные кадровые поля пока доступны только для чтения; свои контакты можно менять. Это минимальный HR-сценарий, без полного кадрового администрирования.

Доказательства: backend/test/roles.test.ts, HR-01, frontend/src/pages/EmployeesPage.tsx. В браузере проверены вход HR, поиск сотрудника, просмотр истории, отсутствие кнопок решения и сохранность после обновления. Рабочие три заявки и остаток Айданы 13 дней сохранились после миграции и перезапуска.

### Лишние данные API — исправлено

Сотрудник получает только собственную запись employees; имя руководителя уже есть в ней. Руководитель получает себя и прямых подчинённых, без дат приёма подчинённых. HR получает рабочие кадровые сведения только своей компании. Чужие профили, даты рождения, личные контакты, уведомления и результаты обучения не выдаются HR. Поля сотрудников и собственных профилей возвращаются по явному списку: дополнительные JSON-поля не попадают в ответ автоматически.

Доказательства: backend/src/workflow.ts, HR-02, backend/test/roles.test.ts: разделение компаний, запрет действий HR, защита неизвестных полей и повторный seed без потери данных.

### Инструкции AI Jana — исправлено

База знаний обновлена до версии 1.4: отдельные аккаунты вместо выбора демо-роли; PostgreSQL и серверное сохранение прогресса, контактов и списаний; удалены инструкции по отсутствующей кнопке сброса. Описаны реальные границы HR-кабинета. Ссылки на источники и отказ вне базы сохранены. Внешняя LLM не подключалась.

Доказательства: frontend/src/mocks/knowledge.ts, дополнительные тесты ассистента, HR-06 и HR-07. В браузере ответ о прогрессе содержит серверное сохранение и источник «Прогресс и завершение курса».

## Рекомендуемое и необязательное

- [ ] RU/KZ: переключения языка или выделенного слоя локализации не найдено. Поле `language` в профиле не переводит интерфейс. На странице 17 это пожелание, а не обязательный минимум.
- [ ] Docker / docker compose: файлов запуска не найдено. Для Digital HR это **приветствуется**, но не обязательно (страница 19). Обязательный `docker compose up`, офлайн-разбор и метрики адресов относятся к **Challenge 01 / Jana Address**, а не к нашему кейсу.
- [x] Второй тип заявки «Аванс» не нужен для выполнения минимума: достаточно рабочего отпуска. Старые mock-авансы и TS-тип не считаются серверной реализацией аванса.
- [x] Реальные 1С:ЗУП/Documentolog, ЭЦП, хранение оригиналов кадровых документов, нативное мобильное приложение, рекрутинг, Performance Management и кадровые решения AI не обязательны для этого MVP.

## Как повторить проверку

Сначала запустить локальный PostgreSQL по README (`backend`: `pnpm dev:local`). Из корня:

```powershell
node scripts/audit-hackathon.mjs
```

Команда запускает регрессионные тесты, отдельные проверки PDF, TypeScript и сборки; обновляет [машинный результат](hackathon-audit/results.json) и логи. **Последний код возврата — 0:** регрессионные тесты, восемь проверок PDF и сборки прошли. Это не подтверждение всего ТЗ: схема описывает будущие, ещё не реализованные интеграции; пункты сдачи и ручных проверок отмечены отдельно. Ожидания исходных проверок PDF сохранены. Последний аудит включает файлы архитектуры, презентацию и исходники в индексе Git. Логи создаются локально и исключены из публикации; машинный JSON содержит итоговые результаты.
