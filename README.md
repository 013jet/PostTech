# PostTech · JanaМен

React + TypeScript + Vite, локальный API на Node.js + TypeScript + Fastify, PostgreSQL. Вход, профиль, заявки, решения, история, остаток отпуска, Academy и уведомления подключены к серверу. AI Jana пока использует локальную тестовую базу знаний. Все сотрудники вымышлены.

## Локальный запуск

Требуются Node.js 24.x и pnpm 11.25.0. Из корня репозитория в первом терминале:

```powershell
cd backend
pnpm install --frozen-lockfile
pnpm dev:local
```

Запускается настоящий PostgreSQL на `127.0.0.1:55432`, применяются миграции и создаются отсутствующие тестовые аккаунты. API: `127.0.0.1:3001`. Системная установка PostgreSQL и Docker не нужны; существующие записи не сбрасываются.

Во втором терминале:

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открыть [кабинет](http://127.0.0.1:5173/).

| Аккаунт | Email | Пароль локального стенда |
|---|---|---|
| Сотрудник — Айдана | `employee@janamen.local` | `JanaLocal2026!` |
| Руководитель — Данияр | `manager@janamen.local` | `JanaLocal2026!` |
| HR-администратор — Мадина | `hr@janamen.local` | `JanaLocal2026!` |

HR видит каталог сотрудников и заявки только своей компании: поиск, статусы, карточки и история. Решение по отпуску остаётся у прямого руководителя. Чужие личные контакты, даты рождения, учебные ответы и результаты HR не получает. В профиле каждой роли можно менять только собственные контакты; официальные кадровые поля доступны для чтения.

Для одновременной работы открыть сотрудника на `http://127.0.0.1:5173/`, руководителя на `http://localhost:5173/`. У этих адресов отдельные cookie, но общая серверная база. Две вкладки одного адреса используют одну сессию.

## Проверка сценария

1. Войти сотрудником и подать отпуск. Номер и историю создаёт сервер.
2. Войти руководителем, обновить список и принять решение с комментарием.
3. Обновить кабинет сотрудника: проверить уведомление, статус и остаток.
4. Обновить страницу и перезапустить `pnpm dev:local`: записи и списание сохраняются.

Данные обновляются каждые 15 секунд при видимой вкладке, при возвращении в окно и по кнопке. Исходный остаток Айданы в новой базе — 18 дней. Старые браузерные заявки автоматически не импортируются; прежнее сохранение не удаляется.

В Jana Academy сотрудникам Айдане и Тимуру назначены два учебных курса. Сервер сохраняет пройденные материалы, ответы, попытки и результат; завершение курса создаёт одно уведомление. Тест доступен после всех материалов, проходной балл — 80%. Новый серверный прогресс начинается с нуля; прежний прогресс браузерного прототипа не импортируется.

База и её случайный пароль находятся в `backend/.local/`, исключены из Git. Не удаляйте эту папку для обычного перезапуска. Для остановки серверов — Ctrl+C в соответствующем терминале.

В каждой папке есть `pnpm test` и `pnpm build`. Тестам API нужен работающий PostgreSQL; они создают и удаляют только собственную временную схему. Подробности: [бэкенд и API](backend/README.md), [фронтенд](frontend/README.md).

Локальный сервер привязан к loopback. Облачный демонстрационный стенд использует отдельную базу Neon; данные локальной разработки в неё не копируются. Все аккаунты и сотрудники демонстрационные.

## Развёртывание на Vercel

Демонстрационный сайт: https://posttech.vercel.app. Вход — три аккаунта из таблицы выше. Заявки, остаток отпуска и прогресс обучения меняются во время демонстраций и проверок. Результаты проверки опубликованного сайта сохранены в `reports/`: мобильные сценарии отпуска, Academy, AI Jana, уведомлений и профиля. Проверки проводились в браузере при ширине 360 и 390 px; физические телефоны не использовались.

Корневой `vercel.json` размещает Vite и Fastify в одном проекте: `/api/*` направляется в стандартную Node.js Function `api/index.mjs`, остальные пути — во фронтенд. API собирается в `backend/cloud/index.mjs`, чтобы сохранить ESM при упаковке функции. Артефакт создаётся командой `pnpm run build:vercel` и исключён из Git. Vercel пересобирает его при публикации. Для локальной разработки по-прежнему используется `pnpm dev:local`.

База Neon подключена через Marketplace на бесплатном тарифе. `DATABASE_URL` хранится в переменных Vercel, миграции применяются отдельно через прямое соединение `DATABASE_URL_UNPOOLED`; они не запускаются при каждом запросе. Перед релизом нужно выполнить `pnpm test`, `pnpm build` в обеих папках и `pnpm run build:vercel` в backend, затем развернуть корень проекта командой `vercel deploy --prod` из авторизованного CLI.

API доверяет только точным доменам из `VERCEL_URL`, `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_BRANCH_URL`; дополнительный домен требует явного `ALLOWED_HOSTS`. Cookies в облаке имеют `Secure`, `HttpOnly`, `SameSite=Strict`; проверка Origin и служебного заголовка остаётся включённой. `.vercelignore` исключает локальную базу, секреты, временные файлы и презентации из загрузки.

AI Jana работает по тестовой базе знаний. Интеграции 1С:ЗУП и Documentolog описаны в архитектуре и пока не подключены.

[Көрнекі архитектура / интерактивная схема](docs/architecture.html) · [SVG](docs/architecture.svg) · [PNG для презентации](docs/architecture.png) · [Интеграциялар сипаттамасы / описание интеграций](docs/INTEGRATIONS.md).

Схема отличает текущие React → Fastify → PostgreSQL и локальную базу знаний AI от будущих компонентов. Описание задаёт чтение кадровых данных из 1С:ЗУП, создание документов в Documentolog после решения руководителя, отдельные статусы доставки и документа, сопоставление идентификаторов, outbox/inbox, защиту доступа и восстановление после сбоев. Импорт баланса выделен в отдельный этап с защитой от двойного списания. Это проект подключения: адаптеры, фоновые процессы и внешние вызовы ещё не реализованы; конкретные версии продуктов и API нужно согласовать.
