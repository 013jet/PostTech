# JanaМен: архитектура және болашақ интеграциялар

Күні: 17.10.2026. Мәртебесі: **іске асыруға ұсынылған жоба**, нақты интеграция емес.

[Көрнекі архитектураны ашу](architecture.html) · [SVG](architecture.svg) · [PNG](architecture.png)

HTML — негізгі көрнекі нұсқа; SVG және PNG — презентацияға арналған ашық түсті экспорттар. HTML интерактивті басқаруының синтаксисі тексерілді; браузердің файл қауіпсіздігіне байланысты интерактивті әрекеттер мен тар экрандағы көрініс шолғышта расталмады. PNG схемасы бөлек көрсетіліп тексерілді.

Схема HTML ішінде сақталады. Өзгерткеннен кейін SVG-ді қайта алу: жоба түбірінде `node scripts/export-architecture.mjs`. PNG — осы SVG-ден алынған статикалық көрініс; схема өзгерсе, оны да жаңарту керек.

## Қазір не жұмыс істейді

React + TypeScript + Vite интерфейсі Fastify API-ге жүгінеді. PostgreSQL аккаунттарды, сессияларды, профильдерді, өтініштерді, демалыс күндерінің шегерілуін, тарихты, хабарламаларды және Academy нәтижелерін сақтайды. AI Jana браузердегі дайын анықтамалықтан жауап береді; жеке профильдерді немесе сыртқы жүйелерді оқымайды.

Сервер қызметкерге өз деректерін, басшыға тікелей бағыныштыларын, HR-ға өз компаниясының рұқсат етілген жұмыс деректерін қайтарады. Басшының шешімі, күндерді шегеру, тарих және хабарлама бір PostgreSQL транзакциясында сақталады. Қазір қол қою, сыртқы жіберілім кезегі, интеграция кестелері, worker, webhook және интеграция әкімші беті **жоқ**.

Кодтағы негіз: [маршруттар](../backend/src/app.ts), [өтініш транзакциялары және деректерді шектеу](../backend/src/workflow.ts), [Academy](../backend/src/academy.ts), [SQL схемалары](../backend/migrations/), [AI анықтамалығы](../frontend/src/mocks/knowledge.ts).

Қолданыстағы сервер тек loopback-та жұмыс істейді. Cookie әзірге жергілікті HTTP үшін бапталған. Бұл схема оны өндірістік орналастыруға дайын деп есептемейді.

## Схемадағы шекаралар

Тұтас жақтау — іске асқан компонент. «Жоспар» белгісі және үзік жақтау — қосылмаған компонент. Жебе деректер бағытын көрсетеді; 1С импортының HTTP сұрауын worker бастайды, ал жебе жауаптағы деректердің 1С-тен келуін көрсетеді.

Браузер тек JanaМен API-ін пайдаланады. Сыртқы жүйелердің сервистік құпиялары браузерге берілмейді. Fastify бизнес ережелерді орындайды; болашақ интеграция модулі провайдер пішімдерін ішкі пішімге түрлендіреді. Фондық worker жеткізу мен қайталауды басқарады. Бірінші нұсқада PostgreSQL outbox кезегі жеткілікті; жеке message broker міндетті емес.

Жоспарланған код шекарасы: backend/src/integrations/ ішіндегі zup-adapter, documentolog-adapter, worker және бөлек machine-auth қабылдағыш. Бұл атаулар — болашақ модульдер, қазір жасалған файлдар емес.

## 1С:ЗУП → JanaМен: кадрлық деректерді оқу

1. Бөлек сервистік аккаунт тек қажетті ұйымдар мен оқылатын өрістерге қол жеткізеді. Worker HTTPS арқылы өзгерістерді сұрайды. Өзгеріс курсоры мен парақтау қолдауы нақты 1С конфигурациясымен келісіледі.
2. Бейімдегіш жауапты тексереді: компания, қызметкер, еңбек қатынасы, бөлім және басшы идентификаторлары; өзгеріс нұсқасы; күн форматы. Уақыт UTC, кадрлық күндер YYYY-MM-DD түрінде сақталады.
3. Сәйкестік external_company_id + external_employment_id арқылы жасалады. external_person_id бөлек сақталады: бір адамда бірнеше еңбек қатынасы болуы мүмкін. Email, аты-жөні немесе ЖСН негізгі сәйкестік кілті болмайды. Қазіргі employees.id сақталады.
4. Импорт алдымен staging аймағына түседі. Бір парақтағы барлық жазба жарамды болып, сол парақ транзакцияда сақталғанда ғана курсор жылжиды. Жарамсыз парақ карантинге түседі; оның курсоры алға жылжымайды. Қайта өңдеу сол нұсқаны қайталамайды. Ескі нұсқа жаңа мәліметті баспайды. Бір толық импорт үшін shared snapshot token немесе толық аяқталғаннан кейін бір рет ауыстыру қажет.
5. Басшы басқа парақта келсе, байланыс кейін шешіледі. Компания шекарасы немесе белгісіз тұлға сәйкес келмесе, автоматты біріктіру жасалмайды; HR тексеретін қате пайда болады. Компания ауысуы мен басшы ауысуы — құқыққа әсер ететін жеке бақыланатын операция.
6. Жұмыстан шығу мәртебесі расталғанда белсенді сессияларды тоқтату және жаңа әрекеттерді жабу іске асырылады; бұрынғы тарих жойылмайды. Толық тізімде кездеспеу өздігінен жұмыстан шығу деп саналмайды.

**Тасымалдау таңдауы — жобалық ұсыныс:** нақты конфигурацияда шектеулі JSON қайтаратын арнайы HTTP-сервис; балама — рұқсаттары шектелген OData. 1С платформасы [арнайы HTTP-сервистерді](https://v8.1c.ru/platforma/http-servisy/) және [REST интерфейсін](https://v8.1c.ru/platforma/rest-interfeys/) қолдайды. Бұл нақты ЗУП нұсқасында дайын кадрлық endpoint бар дегенді білдірмейді. Метадерек атаулары мен Қазақстанға арналған конфигурация нұсқасы әлі белгісіз.

Ішкі бейімдегіш келісімінің мысалы, **провайдердің API жауабы емес**:

```json
{
  "schemaVersion": "zup-personnel.v1",
  "externalCompanyId": "example-company-guid",
  "externalEmploymentId": "example-employment-guid",
  "externalPersonId": "example-person-guid",
  "externalManagerEmploymentId": "example-manager-guid",
  "sourceRevision": "opaque-revision",
  "effectiveDate": "2026-10-17",
  "employmentStatus": "active",
  "fields": {
    "name": "Тест қызметкері",
    "position": "Логистика маманы",
    "department": "Операциялық бөлім",
    "hiredAt": "2025-03-10"
  }
}
```

Алғашқы кезеңде импорт тек кадрлық өрістерді жаңартады. contacts, рөлдер, парольдер, сессиялар, өтініштер, Academy және vacation_debits импортпен алмастырылмайды. Жалақы, банк деректері және ЖСН бастапқы импортқа кірмейді. Жаңа employees жолдары, JSON өрістері мен басшы байланыстары бөлек миграция және тестпен енгізіледі.

### Демалыс қалдығын қосарлы шегерусіз көшіру

Қазіргі есеп өзгермейді: opening_days − жергілікті шегерулер. 1С-тен алынған ағымдағы қалдықты opening_days өрісіне тікелей жазуға болмайды: оның ішінде бұрынғы мақұлдаулар ескерілген болуы мүмкін.

Баланс интеграциясының жеке кезеңінде source_balance, source_revision, as_of және 1С есебіне кірген жергілікті requestId сәйкестіктері сақталады. Ұсынылған есеп: **қолжетімді күн = 1С расталған қалдығы − оған әлі кірмеген жергілікті мақұлдаулар**. Қалдық пен ескерілген өтініштердің жиыны бір есептік кесіндіге жатуы керек. 1С-ке өтінішті автоматты тіркеу бұл алғашқы read-only импортқа кірмейді; есепке кіру фактісі расталған салыстыру арқылы беріледі.

1С жергілікті requestId-мен салыстыруға жеткілікті ақпарат бермесе, автоматты баланс импорты қосылмайды. Қайта бастапқы қалдықты есептеу немесе күндерді қайтару HR тексерген жеке операция болады. Мақұлдау блокировкасы мен салыстыру бір қызметкерге ортақ транзакциялық құлыпты пайдалануы тиіс. Documentolog оқиғасы күн шегеретін операцияны шақырмайды.

## JanaМен ↔ Documentolog: өтініштен құжатқа

1. Қызметкер өтініш береді; тек тікелей басшы шешім қабылдайды. Жоспарланған құжат ағыны **мақұлдаудан кейін** басталады. Құжат үлгісі, қол қоюшылар және корпоративтік рәсім HR-мен алдын ала келісіледі.
2. Мақұлдау транзакциясы қолданыстағы жазбалармен бірге outbox оқиғасын қосады. Оқиға кілті requestId + approvalRevision + templateVersion болады. Worker оқиғаны транзакция аяқталғаннан кейін ғана алады; сыртқы HTTP шақыру SQL транзакциясының ішінде орындалмайды.
3. Worker қызметкердің сыртқы сәйкестігін және бекітілген үлгіні тексереді. Тек қажетті аты-жөн, ұйым, өтініш нөмірі және демалыс даталары жіберіледі. Қол қоюға провайдер талап ететін қосымша деректер керек болса, олардың қажеттілігі бөлек келісіледі. Жеке байланыстар мен оқыту нәтижелері әдепкі жіберілімге кірмейді.
4. Бейімдегіш құжатты жасап, external_document_id мәнін компания және өтінішпен байланыстырады. Қол қою жіберілімі бөлек бизнес әрекет деп қаралады. Провайдер құжатты жасау кезінде бірден жіберсе, worker жасауға дейін барлық рұқсат пен үлгіні тексереді.
5. Сыртқы оқиға арнайы HTTPS қабылдағышқа түседі. Сервер провайдермен келісілген түпнұсқалық тексеруді, құжат сәйкестігін және қайталану қорғанысын орындайды. Inbox-қа сенімді сақтау аяқталғаннан кейін ғана қабылданғаны туралы жауап береді. Оқиға жай browser session-мен өңделмейді.
6. Webhook тексеру механизмі немесе мәртебені серверден қайта растау мүмкіндігі жоқ болса, оқиға құжатқа қол қойылды деген дәлел болмайды; жеткізушімен келісілген тексеру не қолмен салыстыру қажет. Polling мәртебе оқу API-і расталса ғана балама болады.
7. Тексерілген нәтиже құжат мәртебесін, интеграция тарихын және тиісті жеке хабарламаны жаңартады. Бір адамның қол қоюы барлық тарап аяқтады деген сөз емес. Рұқсаты бар пайдаланушы ғана құжатты сервер арқылы ашады; сервистік token және толық сыртқы жауап фронтқа берілмейді.

**Провайдер бойынша тексерілген шекара:** [Documentolog Business ресми API нұсқаулығы](https://documentolog.com/en/integrations-business/api) құжат жіберуді және webhook-ты сипаттайды. Ол draft пен қол қою кезегін қолдамайтынын және ашық sandbox жоқ екенін көрсетеді. Бұл шектеулер Documentolog Platform нұсқасына автоматты қолданылмайды. Біздің ұйымда қай өнім қолданылатыны, мәртебе оқу және қауіпсіз callback тәсілі әлі келісілмеген. Қазір ешқандай нақты құжат жіберілген жоқ.

Үш күй бөлек сақталады:

| Қабат | Жоспарланған ішкі күйлер | Кім өзгертеді |
|---|---|---|
| Өтініш | pending / approved / rejected / cancelled | Қолданыстағы JanaМен ережелері |
| Жеткізу | queued / processing / retry_wait / sent / needs_review | Worker және бақыланатын қайта өңдеу |
| Құжат | not_created / sent / signing / signed / declined / failed | Тексерілген провайдер дерегінің бейімдегіші |

Бұл құжат күйлері — ішкі жобалық сөздік, провайдердің нақты enum-ы емес. signed өтінішті автоматты completed етпейді; declined approved мәртебесін автоматты rejected етпейді. Басшы шешімін кері өзгерту, мақұлданған демалысты жою және күнді қайтару қазір қолдау таппайды; мұндай жағдай HR-дың жеке бизнес рәсімін қажет етеді.

## Қайталау, ақау және қауіпсіздік

- **1С қолжетімсіз:** соңғы жарамды көшірме қалады; болашақ UI lastSyncedAt және ескіргенін көрсетеді. Расталған тоқтатылған аккаунт қайта ашылмайды. Қауіпсіз ескіру шегі конфигурацияда келісілген соң, мерзімі өткен кадр/баланс дерегімен жаңа беру және мақұлдау жабылады; қарау мен жаңарту ашық қалады. Бұл шектеу қазір іске аспаған.
- **Documentolog қолжетімсіз:** өтініш пен басшы шешімі сақталады; құжат жеткізуі күтуде болады. API «құжат жіберілді» деп жалған нәтиже бермейді. Қайта әрекет SQL шешімін және күн шегеруді қайталамайды.
- **Жасау сұрауы timeout берді:** сыртта құжат жасалып үлгеруі мүмкін. Провайдердің idempotency немесе external reference бойынша іздеу мүмкіндігі расталса, сол кілтпен салыстыру жасалады. Ондай мүмкіндік болмаса, needs_review күйіне жіберіледі; жасау сұрауы соқыр қайталанбайды. Exactly-once жеткізуге уәде берілмейді.
- **Worker тоқтады:** оқиға PostgreSQL-де қалады. Қысқа lease мерзімі, FOR UPDATE SKIP LOCKED алу және attempt саны worker-дің қайта жалғастыруына көмектеседі. HTTP кезінде ұзақ SQL құлпы ұсталмайды. Қайта өңделетін inbox оқиғалары да сенімді кезекте сақталады.
- **Қайталанған немесе ретсіз callback:** inbox dedupe кілті және нұсқа тексеруі қолданылады. Провайдер eventId бермесе, құжат пен расталған күй нұсқасынан тұрақты кілт жасалады. Белгісіз не ескі оқиға signed күйін кері түсірмейді; күмәнді қайшылық карантинге кетеді.
- **Қате түрлері:** уақытша желі/5xx және келісілген rate limit үшін кідіріс өсіріліп, jitter қосылып, Retry-After ескеріледі. 401/403 — қолжетімділік қатесі, құжат жасау жалғаспайды; 4xx валидация — түзетуге беріледі. Шек асқанда операторға белгі түседі. Нақты таймаут пен retry шектері жүктеме тексерісінде таңдалады.
- **Құпиялар мен желі:** сервистік аккаунттар бөлек, ең аз құқықпен; HTTPS, қорғалған secret store және ротация жоспарланады. Өндірісте Secure cookie, TLS және reverse proxy қажет. Қазіргі loopback/Origin/CSRF тексерулерін өшіріп webhook ашуға болмайды; machine-auth қабылдағыш жеке шекара болады.
- **Құжат файлдары:** провайдерге толық PostgreSQL немесе жабық каталог ашылмайды. Қажет болса, тек бекітілген storage хостынан бір құжатқа арналған уақытша сілтеме беріледі. Тіркемелердің форматы, өлшемі және URL allowlist тексеріледі; callback-тегі кез келген URL автоматты жүктелмейді. Қол қою token-ы мен жабық сілтемелер журналға жазылмайды.
- **Құқық пен аудит:** сыртқы companyId ешқашан браузерден сенімді деп алынбайды. Әр сыртқы ID ішкі компаниямен байланысады. Компания ауқымы болашақта JSON company атауынан тұрақты company_id кілтіне көшеді. Импорт рөл қоспайды. Аудит correlationId, жүйе, әрекет, уақыт, нәтиже мен нұсқаны сақтайды; пароль, token, толық жеке payload сақталмайды.

## Жоспарланған сақтау құрылымы

Төмендегі кестелер мен өрістер **қазіргі БД-да жоқ**, бұл ұсыныс. Миграциялар осы тапсырмада жасалмайды.

| Ұсынылатын құрылым | Мақсаты және шектеуі |
|---|---|
| companies, company_id | Компанияның тұрақты шекарасы; қызметкер, mapping және құжатқа бірдей қолданылады |
| external_employee_links | UNIQUE(system, external_company_id, external_employment_id); ішкі employee_id және personId сәйкестігі |
| personnel_staging, sync_cursors | Нұсқаны тексеру, жарамсыз парақты бөлек сақтау, соңғы толық/ішінара импорт ізі |
| integration_outbox | UNIQUE(event_key); payload_version, status, attempt, next_attempt_at, lease_until, correlation_id |
| external_documents | request_id, company_id, approval_revision, template_version, external_id, document_status; байланыстыруға UNIQUE кілттер |
| integration_inbox | UNIQUE(system, event_key); қабылдау/өңдеу мәртебесі және қауіпсіз қысқаша оқиға |
| integration_audit | Өзгермейтін әрекет ізі; сыртқы қате мазмұны тазартылған түрде |
| leave_balance_snapshots, leave_reconciliation | Бір кесіндідегі 1С қалдығы және оған кірген request_id тізімі; атомарлы салыстыру |

## Қосу реті және қабылдау шарттары

1. **Келісім:** ЗУП өнімі/нұсқасы, Documentolog Business не Platform, ұйым идентификаторлары, желі, рұқсат, деректердің құрамы және құжат үлгісі анықталады. Өнім құжаттамасы, callback қауіпсіздігі, idempotency және мәртебе оқу мүмкіндігі жазбаша расталады.
2. **1С оқу прототипі:** жалған адаптермен mapping, парақтау, дубль, ескі нұсқа, белгісіз басшы, жұмыс мәртебесі және бөтен компания тексеріледі. Contacts пен рөл өзгермеуі тиіс. Келісілген оқшауланған контурсыз нақты кадр деректері қолданылмайды.
3. **Outbox және құжат прототипі:** SQL rollback оқиға қалдырмайды; commit оқиға қалдырады; worker құлауы оқиғаны жоғалтпайды; timeout күмәнді құжатты дубльдамайды. Сыртқы HTTP mock арқылы тексеріледі. Нақты қол қою — провайдермен келісілген бөлек кезең.
4. **Callback және UI:** жалған, қайталанған, ретсіз және басқа компанияның оқиғалары сыналады. Өтініш мәртебесі мен ledger өзгермеуі тиіс; тек рұқсат етілген құжат мәртебесі және бір хабарлама жаңарады. Ескірген дерек пен retry/needs_review пайдаланушыға түсінікті көрсетіледі.
5. **Баланс салыстыруы:** бір мақұлдау 1С есебіне дейін де, кіргеннен кейін де бір рет қана шегеріледі. Параллель мақұлдау мен импорт бір кесіндіде тексеріледі. Сәйкестік дәлелденбейінше бұл кезең қосылмайды.
6. **Пилот:** аудит, қалпына келтіру, қолжетімділікті тоқтату, құжат рұқсаты, журналдарды тазарту және қосқыштарды кері өшіру тексеріледі. Интеграциялар әдепкі өшірулі басталып, компания бойынша біртіндеп қосылады.
